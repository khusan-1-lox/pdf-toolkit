# i18n RU/EN with next-intl Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Добавить полную двуязычность RU/EN в pdf-toolkit/frontend через next-intl с роутингом `[locale]` (always prefix, default `en`) без смешанного языка.

**Architecture:** `middleware` → `app/[locale]/layout.tsx` (NextIntlClientProvider) → `app/[locale]/page.tsx` и `app/[locale]/tools/[slug]/page.tsx` (useTranslations); `routing.ts` + `i18n.ts` + `messages/*.json` + `LocaleSwitcher` в Header; `next.config.mjs` обернут `createNextIntlPlugin`.

**Tech Stack:** Next.js 14.2.0 (App Router), React 18.3, next-intl@3.26.5, TypeScript 5.4, Tailwind 3.4

**Spec:** `docs/superpowers/specs/2026-09-01-i18n-next-intl-design.md` (зеркало: `pdf-toolkit/docs/superpowers/specs/2026-09-01-i18n-next-intl-design.md`)

## Global Constraints

- Next.js `14.2.0` — не обновлять мажор, next-intl `3.26.5` (последняя 3.x для Next 14)
- Locales `['en','ru']`, defaultLocale `'en'`, localePrefix `'always'` — вербатим из спека
- `app/api/**` вне `[locale]`, matcher исключает `api`, `_next`, `.*\..*`
- Сохранить `rewrites /api/:path* → API_URL/api/:path*` и все security headers из `next.config.mjs`
- `<html lang={locale}>` + `alternates.languages` (`en`/`ru`/`x-default`→`/en`)
- Сообщения бэкенда остаются EN, фронт мапит через `friendlyError` → `t('errors.*')`
- Файлы/стейт tool-страницы не сбрасываются при смене локали (replace pathname)
